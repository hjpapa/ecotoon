# 충주용산초경제툰

초등학교 1~6학년을 위한 경제·노동·금융 웹툰 사이트입니다. 학년마다 15편(영역별 5편), 이야기마다 8장면으로 총 90편·720장면을 제공합니다.

지우와 하린은 학년이 올라가며 외형과 말투가 자랍니다. 각 이야기에는 전용 삽화 8장면이 있습니다. 같은 대표 그림을 여러 이야기에 돌려 쓰지 않고, 사건에 따라 시선·손동작·자세·표정·구도가 달라집니다. 말풍선은 그림과 함께 표시되며 작은 화면에서도 읽을 수 있도록 높이가 늘어납니다. 두 친구의 좌우 자리가 바뀐 장면은 `reverseSpeakers`로 말풍선 방향을 맞춥니다. 장면 설명은 그림 위에 두어 얼굴을 가리지 않습니다.

모든 이야기는 생활 사건에서 시작해 서로 다른 생각, 선택, 결과로 이어집니다. 각 편에는 상황을 여는 소개와 8개의 행동 묘사, 장면마다 주고받는 두 말풍선이 있습니다. 저학년은 장터·집안일·소풍·저축 경험을, 중학년은 파티·지역 조사·학교 축제를, 고학년은 모의 장터·교류·창업 프로젝트를 중심으로 전개합니다. 학습 주제명과 이야기 제목을 함께 표시하며, 개념 정리는 이야기를 읽은 뒤 만납니다.

18편의 전개를 추가로 보강했습니다. 동전을 놓쳐 찾아보는 사건, 바퀴가 멈춰 소풍에 늦을 위기, 빌린 놀이 돈을 선물로 착각한 선택, 판매금과 임금을 혼동한 봉투, 실행하다 실패한 창업 시제품처럼 구체적인 문제를 해결하며 개념을 발견합니다. 결과가 아쉽거나 계획을 수정해야 하는 장면에서는 표정도 그 상황에 맞춥니다.

## 실행

빌드나 패키지 설치 없이 정적 웹 서버로 실행합니다.

```sh
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000`을 엽니다. Windows에서는 `python -m http.server 8000 --bind 127.0.0.1`로 실행할 수 있습니다. 빌드 과정은 필요하지 않습니다.

Vercel 설정은 `vercel.json`에 있고, `.vercelignore`의 허용 목록으로 실제 서비스 파일만 배포합니다. 대상은 `index.html`, `style.css`, `growth.css`, `reader.css`, `catalog.js`, `glossary.js`, `games.js`, `flow.js`, `reader.js`, `app.js`, `vercel.json`과 사용 중인 WebP 삽화입니다. PNG 참고 원본, `production/`, `scripts/`, `docs/`, 이전 버전의 `stories.js`·`curriculum.js`, 로컬 환경 파일과 검증 결과는 배포에서 제외합니다. 원본과 제작 자료는 저장소에 보관합니다. 다른 정적 호스팅에도 같은 파일 목록을 사용하세요.

새 CSS·JS·이미지를 추가할 때는 `.vercelignore`도 함께 갱신하고 배포 검사를 실행하세요. 이 허용 목록은 배포 파일을 줄이며, 첫 화면 이미지 전송량을 줄이는 썸네일 작업은 개선 계획 WP8에서 별도로 진행합니다.

## 이야기와 게임

- `catalog.js`: 요청한 학년별 주제, 8장면 대사, 학습 원칙, 퀴즈, 생활 활동, 게임 데이터
- `app.js`: 학년·영역 필터, 웹툰 읽기, 활동 저장, 게임 열기, 학습 기록
- `flow.js`: 5단계 정의, 이야기 주소 해석, 기존 기록의 진행 표시, 같은 학년의 다음 이야기와 완주 집계
- `games.js`: 금액 만들기, 짝 연결, 순서 잇기, 상황 분류, 예산 세우기, 가상 분산 실험
- `growth.css`: 이야기별 그림의 장면 분리, 만화 안의 말풍선, 모바일 게임 화면
- `assets/episodes/g1-01.webp`~`g6-15.webp`: 90편의 전용 삽화. 파일 하나마다 2열×4행의 8장면을 시간순으로 담습니다.
- `assets/growth-grade-1.png`~`growth-grade-6.png`: 학년별 캐릭터 원본 참고 그림. 웹툰 본문에는 사용하지 않습니다. 메인의 성장 소개에는 같은 그림의 WebP 파일을 사용합니다.
- `production/storyboards.json`: 90편의 장면별 행동·대사·감정·구도 제작 지시
- `production/generated/`: 생성 이미지의 크기·용량·SHA-256 기록
- `production/review.json`: 90편의 육안 검수, 말풍선 좌우 위치, 그림 수정 이력

본문은 각 편의 실제 이미지 크기에 맞춰 장면을 나눕니다. 표지는 그 이야기의 첫 장면이며, 8장면은 하나의 WebP 파일을 공유하므로 같은 이야기를 읽을 때 그림 파일을 여덟 번 받지 않습니다. 이미지에 `loading="lazy"`를 적용해 화면에 가까운 그림부터 읽습니다. 생성 도구의 원본 PNG는 클라우드의 `/workspace/generated_images/`에 보관하고 사이트에는 압축한 WebP를 배포합니다.

리더 상단의 **웹툰 → 정리 → 퀴즈 → 활동 → 게임**에서 현재 위치와 완료 여부를 확인하고 원하는 단계로 이동할 수 있습니다. 스크롤해도 현재 단계가 갱신됩니다. 고정 요소는 이 상단 도구 모음 하나입니다. 웹툰을 읽는 동안 장면 번호와 진행 바가 나타나고, 장면 번호를 누르면 8개 장면 목록이 펼쳐집니다.

활동에서 **활동 마치고 게임 열기 →**를 누르면 해당 이야기의 게임이 열립니다. 구술·그림 활동을 한 어린이도 완료할 수 있도록 기록 입력은 필수가 아닙니다. 메모를 다시 저장해도 진행 중인 게임과 완료 화면은 유지됩니다. 게임을 끝내면 완료 여부와 최고 별 기록을 보관하며 다시 도전할 수 있습니다. 진행 중인 게임의 세부 상태는 현재 열린 리더에서 유지되며, 리더를 닫거나 새로고침하면 다시 시작합니다.

목록에는 읽기·퀴즈·활동·게임 네 칸을 표시합니다. 기존 v3 스키마와 같이 `read: true`는 읽기와 활동을 함께 마친 기록으로 취급합니다. 따라서 빈 메모라도 활동은 완료입니다. 웹툰·개념 정리의 다음 단계 버튼으로 표시한 중간 완료는 현재 리더에서만 유지하고 새 저장 필드는 만들지 않습니다.

이야기 링크는 `#/g3-05`, `#/g3-05/summary`, `#/g3-05/quiz`, `#/g3-05/activity`, `#/g3-05/game` 형식입니다. **링크 복사**는 현재 이야기와 단계의 주소를 복사하며, 클립보드를 사용할 수 없으면 직접 복사할 주소를 표시합니다. 활동을 마치지 않은 게임 링크에는 잠금 안내가 표시됩니다. 브라우저 뒤로가기는 목록으로, 앞으로가기는 이야기로 이동합니다. 단계와 다음 편 이동은 같은 방문 기록을 갱신합니다. 직접 열린 공유 링크에도 목록으로 돌아갈 방문 기록을 준비합니다.

다음 편은 같은 학년 안에서 이어집니다. 현재 이야기와 일치하는 영역 필터가 있으면 그 영역 안에서만 이동합니다. 마지막 편에서는 학년 진행 상황과 남은 이야기 이어 보기를 제공하며, 15편의 읽기·퀴즈·활동·게임을 모두 마친 경우에만 학년 완주를 표시합니다.

기록은 `localStorage`의 `ecotoon-progress-v3`에 저장됩니다. 이전 버전의 기록은 관련된 새 주제로 옮기고 기존 저장 키는 보존합니다. 기록은 같은 기기·브라우저·사이트 주소에서만 유지되며 다른 기기와 동기화되지 않습니다. 브라우저 저장을 사용할 수 없으면 현재 화면에서 읽기와 게임을 진행할 수 있습니다.

## 검증

Chromium 브라우저에서 90개 이야기의 8장면, 학년·영역 필터, 퀴즈, 게임 잠금·해제, 90개 게임의 완료, 새로고침 후 기록 유지, 이전 기록 이전을 확인했습니다. 320·390·1440px 화면에서 말풍선 경계와 8장면 이동을 확인했습니다.

이야기 개편 후에는 90개의 고유한 이야기 제목·상황 소개, 720개의 행동 묘사와 1,440개의 대사를 확인했습니다. 세 가지 화면 폭에서 전편의 두 말풍선이 겹치거나 잘리지 않는지 확인하고, 기존 기록과 게임 데이터 보존·게임 열기·장면 이동을 검증했습니다.

전용 삽화 개편 후 90편 모두 그림과 대사를 대조했습니다. 동전 개수, 저축 목표, 인물 가림, 모의 활동 장소 등 어긋난 장면을 수정했습니다. Chromium에서 90개 WebP의 해독, 720장면의 중복 여부와 분리 위치, 말풍선 방향을 확인했으며 누락 파일과 JavaScript 오류는 없었습니다. 첫 화면은 지연 로딩으로 90개 중 4개의 이야기 그림만 요청했습니다. 이야기 삽화 전체는 약 32.6MiB이며, 한 편의 8장면은 하나의 파일을 공유합니다.

이야기를 수정할 때는 장면 수와 게임의 해결 가능성을 함께 확인하세요. 금융·무역·계약·창업 활동은 놀이 돈과 가상 상황을 사용합니다.

새 삽화의 누락·파일 중복·장면 순서·실제 크기·체크섬·제작 지시와 대사 일치를 확인하려면 다음 명령을 실행합니다. Node.js의 기본 모듈만 사용합니다.

```sh
node scripts/verify-episodes.cjs
```

배포 대상에서 필요한 파일이 누락되거나 미사용 파일이 포함되지 않았는지 확인하려면 다음 명령을 실행합니다. Node.js와 Git이 필요하며, 패키지 설치나 빌드는 필요하지 않습니다. HTML·CSS와 이야기 데이터의 이미지 참조를 대조하고, Git의 ignore 규칙으로 `.vercelignore`를 검사합니다. 새 동적 에셋 참조 방식을 도입할 때는 이 검사도 갱신하세요.

```sh
node scripts/verify-deployment.cjs
```

WP0에서는 구형 `.panel`·`.speech`·`.comic-scene` 및 미사용 시트 위치 스타일을 제거했습니다. 현재 성장 갤러리의 `.art-0`, 웹툰의 `.integrated-panel`·`.integrated-speech` 등 실제 사용 스타일은 유지합니다. 검증용 스크린샷과 임시 파일은 Git·배포에서 제외되는 `output/playwright/`에 둡니다.

WP0 화면 검증은 Chromium에서 360·390·768·1280px의 메인, 목록, 첫 이야기 리더와 동전 게임을 정리 전 CSS와 비교합니다. 활동 저장 전 잠금과 저장 후 게임 진입도 확인합니다. WP1에서는 상단 고정 요소를 하나로 정리했으며, 전체 화면 리더와 학년별 글자 크기는 WP2에서 이어집니다.

WP1의 주소·학년 이동·기록 호환성 검사는 Node.js만으로 실행합니다.

```sh
node scripts/verify-flow.cjs
```

브라우저 스모크 검사는 개발용 Playwright CLI로 실행합니다. 먼저 정적 서버를 실행한 뒤, 평소 사용하는 브라우저와 분리된 테스트 세션을 여세요. 아래 검사는 **테스트 세션의 localhost 학습 기록을 초기화**합니다. Playwright용 Chromium이 설치되어 있어야 하며, 필요하면 CLI의 `install-browser` 명령을 사용하세요.

```sh
npx --yes --package @playwright/cli playwright-cli -s=ecotoon-wp1 open http://127.0.0.1:8000 --browser chromium
npx --yes --package @playwright/cli playwright-cli -s=ecotoon-wp1 run-code --filename scripts/smoke-flow.cjs
```

검사 범위: 360·390·768·1280px의 단계 이동·표시와 44px 버튼, 스크롤 위치, 직접 링크·뒤로가기·앞으로가기·닫기, 활동/게임 잠금, 진행 중·완료 후 게임 재저장, v3 기록과 이전 버전 기록, 학년·영역별 다음 편과 실제 완주 여부, 링크 복사와 저장 공간 사용 불가 시의 동작입니다. 화면 캡처는 `output/playwright/wp1/`에 저장합니다.

## WP2 읽기 화면

모바일·태블릿(1024px 이하) 리더는 화면 전체를 사용하고, 데스크톱은 최대 1040px 중앙 리더로 표시합니다. 1~2학년은 **한 장면씩**, 3~6학년은 **스크롤 읽기**가 기본입니다. 상단 버튼으로 언제든 전환합니다. 한 장면씩 읽을 때 이전·다음 버튼, 좌우 스와이프, ←/→ 또는 PageUp/PageDown으로 이동합니다. 세로 스크롤과 작은 손 움직임은 장면 넘기기로 처리하지 않습니다. 마지막 장면 뒤에는 개념 정리로 이어집니다.

**전자칠판** 버튼은 창 전체에 한 장면을 보여 줍니다. 대사를 1.5배로 키우며 다음 버튼·→·PageDown을 누를 때마다 말풍선을 하나씩 드러낸 후 다음 장면으로 넘어갑니다. 이전 버튼은 순서를 되돌립니다. Esc는 칠판을 나가 원래 읽기 모드로 돌아가고, 다시 Esc를 누르면 리더를 닫습니다. 지원 브라우저에서는 **화면 꽉 채우기**로 브라우저 전체 화면도 사용할 수 있습니다. 전체 화면을 종료하면 원래 읽기 모드로 돌아갑니다. 좁은 화면에서는 그림과 대사를 세로로 배치하고 대사 영역을 스크롤할 수 있습니다.

말풍선은 그림 아래에 분리해 인물·물건을 가리지 않습니다. 장면 설명은 내레이션 상자로 표시합니다. 대사는 1~2학년 18px, 나머지 학년 16px 이상, 장면 설명은 각각 15px/14px 이상입니다. 버튼은 최소 44×44px이며 리더 보조 글자는 12px 이상으로 조정했습니다. 읽기 모드를 바꿔도 입력 중인 활동과 진행 중인 게임 DOM을 유지합니다. 모드는 해당 리더에서만 유지하며 새 이야기는 학년 기본 모드로 시작합니다.

```sh
node scripts/verify-reader.cjs
npx --yes --package @playwright/cli playwright-cli -s=ecotoon-wp1 run-code --filename scripts/smoke-reader.cjs
```

위 브라우저 검사는 격리된 localhost 테스트 세션에서 실행하며 테스트 활동 기록을 저장합니다. 360·390·768·1280px에서 90편 720장면의 글자 크기·말풍선 경계·버튼 크기와 넘기기·스와이프 이벤트·장면 목록·스크롤 진행 표시를 검사합니다. 1920px에서는 전자칠판 순차 대사, 확대 글자, 키보드, 전체 화면, 모드 전환 뒤 메모·게임 보존을 검사합니다. 캡처는 `output/playwright/wp2/`에 저장합니다. 실제 터치 기기와 교실 리모컨의 하드웨어 동작은 별도 현장 확인이 필요합니다. 아바타·용어 사전·음성 읽기는 계획의 WP8·WP9·WP10에서 이어집니다.

## WP3 개념 정리와 퀴즈

정리 화면은 편별로 고른 **문제 → 선택 → 결과 3장면**, 경제 씨앗, 핵심 용어 풀이로 구성합니다. 기존 삽화를 재사용하며 각 장면을 다시 읽고 정리로 돌아올 수 있습니다. 1~2학년의 씨앗은 한 문장으로 정리했습니다. 용어는 `glossary.js`에 학년별로 모으고 각 이야기의 `terms`가 참조합니다.

90편의 질문을 각각 다르게 작성했습니다. 학년마다 이야기 사건을 묻는 `story` 8문항과 새 상황을 묻는 `apply` 7문항이 있습니다. 정답 위치는 학년별로 1·2·3번이 각각 5개이며 실행 중 무작위로 바꾸지 않습니다. 정답에는 별도 해설을, 오답에는 해당 이야기의 힌트와 장면 다시 보기 버튼을 표시합니다. 상단의 **퀴즈로 돌아가기**로 돌아오면 시도한 답과 피드백이 남습니다. 이 왕복은 방문 기록을 추가하지 않고 활동 메모와 진행 중 게임을 유지합니다.

기록은 기존 `quiz: true`를 그대로 사용합니다. 이전 문항을 완료한 기록도 유지하고 다시 풀 수 있으며, 이미 완료한 뒤 오답을 골라도 기존 완료를 지우지 않습니다. 기존 스토리 ID·삽화·대사·활동·게임 데이터는 보존합니다.

```sh
node scripts/verify-quizzes.cjs
node scripts/verify-quizzes.cjs --write-review
npx --yes --package @playwright/cli playwright-cli -s=ecotoon-wp1 run-code --filename scripts/smoke-quizzes.cjs
```

첫 명령은 질문 중복, 씨앗 문장과 정답의 유사도, 선택지 길이 편차, 정답 위치 분포, 학년별 글자 수, 힌트 장면과 용어 참조를 검사합니다. 두 번째 명령은 같은 검사를 거쳐 `production/quiz-review.md`를 재생성합니다. 문항이나 용어를 고친 뒤 검수표도 갱신하세요. 검수표는 생성 파일이므로 교사의 검토 의견은 별도 문서나 PR에 남기세요. 자동 검사 통과와 교사 검수는 별개이며, 검수표의 모든 문항은 교사 검수 대기로 표시합니다.

이번 편집 기준(공백 포함)은 1~2학년 질문 50자·선택지 18자, 3~4학년 65자·28자, 5~6학년 80자·38자 이하입니다. 최장/최단 선택지 길이 비율은 1.6 이하, 정규화한 씨앗-정답의 2글자 묶음 Dice 유사도는 0.65 미만으로 제한합니다. 숫자 검사는 오개념의 타당성·난도·정답의 유일성을 보증하지 않으므로 교사 검수표에 실제 근거 대사도 함께 제공합니다.

브라우저 검사는 격리된 localhost 세션의 테스트 기록을 초기화합니다. 360·390·768·1280px에서 90편의 정리, 정답·오답 피드백, 정확한 힌트 장면과 복귀, 기록 보존, 글자·버튼 경계를 확인합니다. 캡처는 `output/playwright/wp3/`에 저장합니다.

## WP4 디자인과 접근성

`design.css`에 브랜드·경제/노동/금융·지우/하린·정답/오답/잠금/힌트 색 토큰을 모았습니다. 보조 글자는 12px 이상, 본문과 카드 설명은 16px이며 기존 학년별 대사 크기는 유지합니다. 밝은 배경의 보조 글씨를 진하게 하고, 비활성 버튼도 글자를 흐리게 만들지 않습니다. 모바일 카드는 한 열, 학년 선택은 두 줄로 배치합니다. 키보드 포커스 표시와 목록 바로 가기를 제공하고 동작 줄이기 설정을 따릅니다.

각 이야기 카드는 `article` 안의 링크 하나입니다. 링크의 이름은 학년·제목, 설명은 도입 문장·학습 진행 상태입니다. Enter로 열고 닫은 뒤 같은 카드로 초점이 돌아옵니다. Ctrl/Cmd 클릭과 가운데 버튼으로 새 탭을 열 수 있습니다. 영역·읽기·진행 아이콘은 `icons.js`의 로컬 SVG로 표시하며 글자 레이블을 함께 유지합니다.

Google Fonts 외부 요청을 제거하고 Noto Sans KR 400·700 WOFF2를 자체 호스팅합니다(합계 약 503KiB). [공식 원본](https://github.com/google/fonts/tree/main/ofl/notosanskr)의 SIL OFL 1.1 라이선스를 `assets/fonts/OFL.txt`와 글꼴 메타데이터에 보존했고 하단에서 열 수 있습니다. 원본 TTF의 SHA-256은 `194018e6b2b293a7964f037b25c0249ce1418bc9ab3c971060a03aa57861e252`입니다. 서브셋은 사이트 문구, KS X 1001 한글 2,350자, 자모·라틴·문장 부호를 포함합니다. 범위 밖 사용자 입력은 시스템 글꼴로 표시합니다. 새로운 문구를 추가할 때 필요한 글자가 없다면 개발용 FontTools/Brotli를 설치하고 `python scripts/subset-fonts.py <원본.ttf>`로 재생성하세요. 서비스 실행에는 Python이나 패키지 설치가 필요 없습니다.

```sh
node scripts/verify-design.cjs
node scripts/verify-deployment.cjs
npx --yes --package @playwright/cli playwright-cli -s=ecotoon-wp4 run-code --filename scripts/smoke-design.cjs
npx --yes --package @playwright/cli playwright-cli -s=ecotoon-wp4 run-code --filename scripts/smoke-flow.cjs
```

디자인 브라우저 검사는 격리된 localhost 기록을 초기화합니다. 360·390·768·1280px의 목록, 리더, 활동·교사 안내, 게임 여섯 유형, 퀴즈 정답·오답에서 글자 크기·계산된 색상 대비(4.5:1)·44px 터치 영역·가로 넘침을 검사합니다. 외부 요청 0건, 로컬 글꼴 두 개 로딩, 링크 구조와 키보드 복귀, 동작 줄이기도 검사합니다. 이미지 속 글자와 운영체제 이모지는 이 대비 계산의 대상이 아니며 스크린리더 실제 낭독은 별도 기기 확인이 필요합니다. 캡처는 `output/playwright/wp4/`에 저장합니다.

## WP5 교실 기능

모바일에서도 상단 **선생님 안내**를 열 수 있습니다. 그 아래 별명 버튼에서 그림과 별명을 만들거나 선택하세요. 별명은 1~12자, 기기당 프로필은 최대 30개이며 실명을 쓰지 않도록 안내합니다. 첫 사용은 ‘새싹’, 이전 학습 기록이 있으면 ‘기존 기록’으로 시작합니다. 목록·나의 활동·리더가 현재 선택한 학생의 기록을 사용합니다. 현재 별명은 목록 상단과 리더 제목에 표시되며 별명·그림을 나중에 바꿀 수 있습니다.

프로필 화면의 **내 기록 파일로 저장**은 현재 프로필만 JSON으로 내려받습니다. 불러오기는 파일의 별명·이야기 수를 보여 준 뒤 새 별명을 확인받아 **별도 프로필**을 만듭니다. 같은 별명이 있으면 다른 별명을 입력해야 합니다. 기존 학생 기록을 병합하거나 덮어쓰지 않습니다. `format: "ecotoon-profile"`, `version: 1`, `profile`, `records`를 가진 이 앱의 백업 파일만 지원하며 파일은 최대 4MiB입니다. 이야기 ID·완료 값·별 개수·메모 타입을 검증합니다. 새 메모 입력은 10,000자까지지만 이전의 긴 메모는 잘라 내지 않습니다.

**학습 기록 지우기**는 현재 별명만 남기고 학습 기록을 비웁니다. **프로필 삭제**는 별명과 학습 기록을 함께 지우며 마지막 프로필에는 사용할 수 없습니다. 두 작업 모두 별명을 보여 주고 확인·취소를 선택하게 합니다. 다른 프로필은 유지합니다. 내려받은 파일은 브라우저 기록 삭제로 함께 지워지지 않으므로 공용 기기의 다운로드 폴더에서도 직접 관리하세요. 프로필은 로그인이 아니며 같은 기기의 모든 사용자가 열 수 있습니다. 서버 수집과 자동 동기화는 없습니다.

`classroom-store.js`는 기존 v3의 `read`, `quiz`, `note`, `gameDone`, `gameStars`를 바꾸지 않고 `ecotoon-classroom-v1` 문서의 프로필별 `records` 안에 저장합니다. 기존 v3 또는 이전 숫자 키 기록을 읽은 뒤 **첫 저장에 성공한 경우에만** 새 문서로 이전하고 이전 키 복사본은 보존합니다. 기존 기록 프로필을 명시적으로 지울 때에는 이전 키의 복사본도 제거합니다. 용량 초과·저장 차단·손상된 문서에는 원본을 덮어쓰지 않습니다. 저장하지 못한 이번 탭의 학습 내용도 파일로 내려받을 수 있습니다. 다른 탭에서 문서가 바뀐 것을 감지하면 저장·전환·삭제를 중단하고 파일 저장 후 새로고침을 안내합니다. 여러 탭에서 동시에 수업하기보다 프로필을 선택한 한 탭을 사용하세요.

```sh
node scripts/verify-classroom.cjs
node scripts/verify-deployment.cjs
npx --yes --package @playwright/cli playwright-cli -s=ecotoon-wp5 run-code --filename scripts/smoke-classroom.cjs
npx --yes --package @playwright/cli playwright-cli -s=ecotoon-wp5 run-code --filename scripts/smoke-flow.cjs
npx --yes --package @playwright/cli playwright-cli -s=ecotoon-wp5 run-code --filename scripts/smoke-design.cjs
```

브라우저 검사는 격리된 localhost 테스트 세션을 사용하고 그 세션의 기록을 초기화합니다. 360·390·768·1280px에서 교사 안내, 두 학생의 메모·퀴즈·게임 상태 분리, 새로고침 복원, 실제 파일 다운로드·불러오기, 잘못된 파일·중복 별명, 삭제 취소·확인, 별명 수정과 초점 복귀를 검사합니다. 두 탭의 충돌 및 저장 차단·용량 초과·손상된 저장소·이전 기록 호환성도 검사합니다. 화면과 테스트 백업 파일은 `output/playwright/wp5/`에 저장합니다. 기존 흐름·디자인 검사도 프로필 저장 형식에 맞춰 갱신했습니다.

## WP6 게임 엔진

게임을 `games/`의 유형별 정적 스크립트로 분리했습니다. `shop`은 목적에 맞춘 선택·이벤트·포기한 선택 돌아보기, `ledger`는 지갑 잔액과 저축 이동, `scenario`는 선택 결과와 재시도를 지원합니다. `simulate`의 9개 계산 모델은 고정 함수이며 문자열 수식을 실행하지 않습니다. 예상 → 서로 다른 값 두 번 실험 → 한 줄 비교를 마치면 탐구 별 세 개를 받습니다. 모델의 숫자는 교실용 가정이며 실제 가격·금리·수익 예측이 아닙니다.

동전은 만들기와 거스름돈 모드, 포트폴리오는 2개 이상의 자산·예상·내 배분/전부 A 막대그래프·결과 비교를 지원합니다. 공통 결과 화면은 `game.wrapUp`과 실제 결과를 연결합니다. 초기 예시는 g1-05, g3-13, g3-14, g4-07에 연결했습니다. 모든 모델의 개발용 예시는 `production/game-examples.json`에 있습니다.

`node scripts/verify-games.cjs`는 90편의 풀이 가능성과 모델의 모든 매개변수 조합을 검사합니다. 격리된 localhost Playwright CLI에서 `run-code --filename scripts/smoke-games.cjs`를 실행하면 360·390·768·1280px의 모든 엔진, 9개 모델, 거스름돈, 키보드와 44px 조작을 검사합니다. 결과 캡처는 `output/playwright/wp6/`에 둡니다.

계획의 기록 호환 규칙을 재확인하여 이전 localStorage 키는 자동 이전 후에도 보존하도록 바로잡았습니다. 사용자가 기존 기록 프로필을 명시적으로 삭제하거나 비울 때에만 이전 복사본도 지웁니다.

## WP7 편별 게임 적용

계획표의 29편을 장보기·시뮬레이션·기입장·상황 선택·분산 실험으로 연결했습니다. 나머지 예산 게임도 장보기로 전환해 정답 목록 노출을 없앴습니다. 장보기는 목적과 물건의 쓰임만 제시하며 예산 변경 이벤트 뒤 다시 계획하고 포기한 대안을 돌아봅니다. 저축 이동은 소비와 구분하고, 대출·금리·물가·환율·교환은 명시된 가상 조건으로 계산합니다.

기존 순서/짝/분류는 6~8개 항목, 카드별 오답 이유, 5~6학년 분류 3개 이상을 갖춥니다. 단위는 데이터로 지정하고 결과 문장은 실제 수행과 연결합니다. `production/game-review.md`는 90편 교사 검수 대기표입니다. 자동 풀이 검증과 교육적 난도 검수는 별개입니다.

`node scripts/build-game-curriculum.cjs`는 보존한 게임 원본과 편집 규칙으로 재생성하며 여러 번 실행해도 중복 항목이 생기지 않습니다. 이야기·삽화·퀴즈에는 손대지 않습니다. `node scripts/verify-games.cjs`는 29편 연결, 항목 수·why·단위와 모든 게임의 풀이 가능성을 확인합니다. `scripts/smoke-games.cjs`는 이제 90편 전체와 9개 모델·거스름돈 예시를 네 화면 폭에서 끝까지 풀고 캡처합니다.

## WP8 이미지와 전송량

목록은 480×320 표지 90장을 사용하고, 리더는 장면별 360px·543px `srcset`을 지연 로딩합니다. 히어로 1장과 성장 6장도 단일 이미지입니다. CSS 확대 크롭을 없앴으며 원본 시트는 저장소와 체크섬 검사에 보존하고 배포에서 제외했습니다. `python scripts/prepare-media.py`는 개발용 Pillow로 파생 이미지와 `production/media-manifest.json`을 재생성합니다.

학년별 두 주인공 아바타는 기존 성장 삽화에서 자른 96px 이미지입니다. 경제 탐험 안내자 **모아**와 네 반응 상태(정답·고민·응원·축하)의 UI 자리를 마련했습니다. 반응은 기존 아바타와 문구를 조합하며, 별도 제작한 표정·포즈 그림은 아닙니다. 동전 게임에는 실제 화폐와 다른 독자 SVG 놀이 돈을 사용합니다.

현재 저장소의 장면 원본은 폭 543px입니다. 예전 `/workspace/generated_images/` PNG 90장은 이 로컬 저장소에 없어 복구·외부 백업 여부를 확인할 수 없습니다. 720/1080px를 새 고해상도 원본인 것처럼 만들지 않고 실제 해상도로 제공합니다. 원본 확보 또는 별도 그림 제작 시 같은 경로와 매니페스트를 갱신할 수 있습니다. 학년별 모델 시트·새 반응 포즈 제작은 별도 미술 작업입니다.

`node scripts/verify-media.cjs`는 이미지 개수·크기·목록 용량을, `node scripts/verify-deployment.cjs`는 사용 파일만 배포되는지 확인합니다. `scripts/smoke-media.cjs`는 네 화면 폭의 새 브라우저 컨텍스트에서 압축 없는 로컬 첫 화면 응답 합계 1.5MB, 목록 전체 이미지 합계 3MB, 개별 장면 로딩을 검사합니다. 전송량은 십진 MB 기준이며 응답 본문 바이트(HTTP 헤더 제외)를 사용합니다.

WP8 로컬 실측(2026-10-14): 첫 화면 360/390px 1,269,293B, 768px 1,293,145B, 1280px 1,308,609B. 전체 목록 이미지 2,130,572B. 90편·720장면 × 4개 폭과 1920px 전자칠판 회귀 검사 통과.

## WP9 대사·예상 질문·수업 자료

90편의 4장면 뒤에 정답 없는 예상 질문 두 선택지를 넣었습니다. 선택은 해당 이야기를 열어 둔 동안만 유지되고 정리 화면에서 결말과 비교합니다. 고르지 않아도 계속 읽을 수 있습니다. 전자칠판에서는 그 장면의 대사를 모두 본 뒤 질문이 나타납니다.

대사는 장면당 0~3개이며 12편에 가족·가게 주인·선생님 등 조연을 추가했습니다. 경제 탐험 안내자 **모아**가 마지막 장면에서 개념을 생활에 연결하고 게임 피드백을 안내합니다. 1~2학년은 한 문장·24자 이하(20자 안팎), 3~4학년 30자, 5~6학년 35자를 검사합니다. 대사 속 핵심어는 점선 밑줄 버튼이며 학년별 `glossary.js` 뜻풀이를 키보드와 터치로 열 수 있습니다.

선생님 안내에서 90편 자료를 선택하거나 이야기·활동의 수업 자료 버튼을 누르세요. 편별 학습 목표, 발문 세 개, 30분 수업 예시, 그림·글 기록 칸을 제공합니다. **활동지 인쇄**는 현재 자료만 A4로 출력하고 학생의 저장 메모는 넣지 않습니다.

`node scripts/build-dialogue.cjs`는 보존한 원래 대사와 `production/pause-prompts.txt`로 재생성합니다. `production/dialogue-review.md`는 현재 대사의 교사 검수 대기표입니다. `production/storyboards.json`은 기존 삽화 생성 프롬프트로 보존합니다. `verify-episodes.cjs`는 그림 관련 장면 설명·순서·화자 좌우·원본 체크섬을 계속 확인하고, 바뀐 웹 대사는 `node scripts/verify-dialogue.cjs`로 검사합니다. 퀴즈 근거 표도 현재 대사에 맞춰 갱신했습니다.

검증: `verify-dialogue`, `verify-episodes`, `verify-quizzes`, `verify-games`, `verify-deployment`; 브라우저 `scripts/smoke-learning.cjs`(네 폭의 예상·뜻풀이·초점·인쇄 및 1920px 조연/침묵 장면), `scripts/smoke-reader.cjs`(90편 × 네 폭과 전자칠판). 실제 교사의 난도·발문 검수는 별도로 남겨 두었습니다.

## WP10 읽어 주기·스탬프와 이어 보기

말풍선의 **▶ 읽기**는 기기에 설치된 한국어 음성이 있을 때 표시됩니다. `getVoices()`와 `voiceschanged`로 늦게 준비되는 음성도 감지합니다. 외부 요청을 늘리지 않도록 `localService === true`인 한국어 음성만 사용하며, 없거나 API를 지원하지 않으면 버튼을 숨깁니다. 장면·읽기 방식·단계 전환, 용어 풀이·수업 자료 열기, 닫기·페이지 이탈 때 재생을 중단합니다. API 동작 기준은 [MDN 음성 목록](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/getVoices), [음성 변경 이벤트](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/voiceschanged_event), [중단](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/cancel), [로컬 음성 속성](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService)을 확인했습니다. 음색·발음은 기기 음성에 따르며 캐릭터별 녹음은 아닙니다.

**나의 활동**과 학년 마지막 화면에 15칸 스탬프판을 표시합니다. 기존 `read`, `quiz`, `gameDone`가 모두 true인 이야기만 도장을 찍고 영역 다섯 편·학년 열다섯 편을 완주하면 배지를 표시합니다. 보상을 별도로 저장하지 않아 프로필 변경·가져오기·삭제 시 현재 기록과 항상 일치합니다. 빈 메모로 그림·구술 활동을 마친 경우도 인정합니다. 스탬프를 누르면 해당 이야기로 이동합니다.

학년 선택과 마지막 이야기·단계는 `ecotoon-library-v1:<profileId>`에 별도로 보관합니다. 프로필마다 구분되고 학습 기록을 비우거나 프로필을 삭제할 때 같이 지웁니다. 저장이 막힌 기기에서도 이번 탭에서 사용할 수 있습니다. 학년을 고르면 회차 목록과 이어 보기 링크를 제공합니다. 저학년 활동의 그림/대화 체크는 기존 `note` 안에 문장으로 저장하여 기록 형식을 유지합니다. 게임 완료 시 해당 시점의 활동 메모(최대 300자 미리보기)와 선택 이유를 비교할 수 있습니다.

검증: `node scripts/verify-rewards.cjs`와 기존 모든 `verify-*.cjs`. 브라우저 `scripts/smoke-speech.cjs`는 API 미지원·빈 목록·조회 오류·지연 음성·외국어/원격 음성 제외·재생/오류/중단 및 1920px 전자칠판을 모의 음성 엔진으로 확인합니다. 실제 스피커의 발음 품질은 기기에서 확인해야 합니다. `scripts/smoke-rewards.cjs`는 네 화면 폭에서 스탬프·배지·새 프로필·삭제·학년 기억·이어 보기·그림 활동 저장을 검사합니다. `smoke-flow`, `smoke-classroom`, `smoke-design`, `smoke-media`도 최종 코드로 통과했습니다. 최종 첫 화면은 네 폭 모두 1.5MB 이하이며 목록 전체 이미지는 2.13MB입니다.

## 개선 계획 진행 상태

WP0~WP10의 로컬 코드 구현과 자동 검증을 완료했습니다. WP4~WP10은 순서대로 검토·병합할 누적 PR이며, 운영 사이트 반영은 해당 PR의 병합 뒤 진행됩니다. 기존 삽화 원본 확보/외부 백업, 720·1080px 고해상도 재제작, 별도 캐릭터 모델 시트·반응 포즈·녹음 파일 제작, 교사의 교육적 검수는 코드 완료와 구분되는 후속 작업입니다. 현재 WebP 원본은 저장소에서 보존합니다.
