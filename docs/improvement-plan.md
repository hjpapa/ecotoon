# 충주용산초경제툰 실사용 개선 계획

> Claude 검토(2026-10-09) → Codex 작업용 문서
> 목표: 학년 수준별 웹툰으로 경제 개념을 쉽게 이해하는 앱을 **실제 수업에 투입할 수 있는 수준**으로 끌어올린다.

## 1. 현재 상태 진단

### 강점 (유지할 것)

- 90편 모두 전용 삽화 8장면을 갖췄다. 화풍이 일관되고, 1학년(둥근 아동형)에서 6학년(청소년형)으로 캐릭터가 실제로 자란다.
- 데이터 구조가 일관된다(`catalog.js`의 `STORIES`). 학년마다 15편이고 경제·노동·금융이 5편씩이다.
- 빌드 없는 정적 사이트라 배포와 유지가 단순하다.
- 계정과 서버 수집이 없어 개인정보 부담이 작다.
- 삽화 검증 스크립트(`scripts/verify-episodes.cjs`)가 있다.

### 핵심 문제 (근거)

| 영역 | 문제 | 근거(측정·분석) |
|---|---|---|
| 학습 흐름 | 단계 안내가 부족하다 | 다섯 단계가 한 화면에 길게 이어져, 지금 어느 단계인지 보이지 않는다. 게임은 "활동 저장하고 읽기 완료" 버튼으로 열리는데, 버튼 이름만으로는 게임이 열린다는 걸 알기 어렵다 |

| 수업 사용 | 교실 환경을 고려하지 않았다 | 모바일에서 "선생님 안내"에 접근할 수 없다. 공용 PC에서는 학생 기록이 섞이고 지울 방법이 없다. 이야기별 주소(링크)가 없고, 전자칠판용 화면이 없다 |

## 2. 목표 경험: 한 편의 학습 흐름 (현행 순서 유지)

순서는 지금 그대로 두고, 각 단계의 역할을 분명히 하고 단계 사이 연결을 매끄럽게 한다.

```
[① 웹툰]      8장면 ─(선택: 4장면 뒤 '멈춤 질문' 너라면?)─ 결말
[② 개념 정리]  3컷 되짚기(문제·선택·결과) → 오늘의 경제 씨앗 → 핵심 용어
[③ 퀴즈]      편마다 고유한 확인 문제. 틀리면 장면 힌트와 "n장면 다시 보기"
[④ 활동]      생활 미션, 내 생각 기록(선택) → "활동 마치고 게임 열기"
[⑤ 게임]      배운 개념을 새 숫자·상황에 적용. 결과를 씨앗 문장과 내 활동에 연결
```

- 리더 상단에 **5단계 표시**(웹툰 · 정리 · 퀴즈 · 활동 · 게임)를 아이콘으로 두고, 현재 위치와 완료 여부를 보여 준다. 단계를 누르면 그 위치로 이동한다.
- 각 단계의 역할은 이렇다. 웹툰은 상황을 겪고, 개념 정리는 이름을 붙이고, 퀴즈는 확인하고, 활동은 생활로 옮기고, 게임은 다른 상황에 적용한다. 게임은 개념을 이미 배운 뒤라 "확인"이 아니라 **"적용"**이 되도록 설계한다(4장).
- 한 편당 목표 시간은 15~20분이다(웹툰 5분, 정리·퀴즈 3분, 활동 3분, 게임 5분). 40분 수업이면 교사 발문 시간이 남는다.
- 게임 결과 화면은 씨앗 문장을 다시 보여 주는 대신 결과와 개념을 잇는다. 예: "여유 돈 1,000원을 남겨 둔 덕분에 주스 값이 올라도 예산을 지켰어요."
- 진행 기록은 현재 스키마(`read`, `quiz`, `note`, `gameDone`, `gameStars`)를 유지한다. 목록 카드에는 **4칸 진행 표시**(읽기·퀴즈·활동·게임)로 보여 준다.

## 3. 웹툰 개선

### 3-1. 읽기 화면(리더)

| 항목 | 현재 | 개선 |
|---|---|---|
| 화면 | 760px 모달 안에서 스크롤 | 모바일·태블릿은 전체 화면(100dvh). 데스크톱은 폭을 넓힌 중앙 리더 |
| 위치 표시 | 1~8 버튼 바가 끝까지 붙어 있고 말풍선과 겹침 | 상단에는 5단계 표시와 얇은 진행 바(웹툰 구간에서만 장면 n/8)만 둔다. 장면 목록은 탭하면 펼친다 |
| 읽기 방식 | 세로 스크롤만 | **스크롤 모드**(3~6학년 기본)와 **한 장면씩 넘기기 모드**(1~2학년 기본: 큰 글씨, 탭·스와이프·←→ 키) |

### 3-2. 말풍선과 글자

- **학년별 최소 글자 크기**(모바일 기준):

  | 요소 | 1~2학년 | 3~4학년 | 5~6학년 |
  |---|---|---|---|
  | 말풍선 | 18px | 16px | 16px |
  | 장면 설명 | 15px | 14px | 14px |
  | UI 보조 글자 | 최소 12px | 최소 12px | 최소 12px |

- **화자 표시**: 말풍선에 학년별 얼굴 아바타(6장 E 에셋)와 이름 색을 붙인다(지우=노랑, 하린=초록, 조연=회색).
- **장면 설명**(caption)은 제목(h3) 대신 웹툰식 내레이션 박스로 바꾸고, 그림 왼쪽 위에 얹는다.
- **핵심 용어 강조**: 대사 속 핵심어(예: 기회비용, 예산, 이자)에 점선 밑줄을 긋고, 탭하면 학년 수준 뜻풀이를 띄운다. 용어 사전은 `glossary.js` 하나로 관리하고 편마다 `terms: ['예산']`으로 연결한다.
- 말풍선이 그림 아래쪽을 덮는 정도(현재 -8%)는 얼굴과 핵심 물건을 가리지 않도록 줄이거나, 말풍선을 그림 아래로 완전히 분리한다.

### 3-3. 이야기 구성(데이터)

- **장면당 대사 수 0~3**을 허용한다. 침묵 컷, 효과음(예: "또르르"), 생각 풍선을 쓴다.
- **조연 화자**를 허용한다(선생님, 가족, 가게 주인, 마스코트). `speech()`는 이미 이름이 다른 화자를 `guest`로 처리하므로, 주로 데이터와 스타일 작업이다.
- **멈춤 질문**: 4장면 뒤에 "너라면 어떻게 할래?"를 묻는다. 정답 없는 예측이어도 되고, 결말 뒤에 "네 예상과 비교해 봐"로 돌아본다.
  - 데이터 예: `pause: { after: 3, question, options: [...], answer: null }`
- **마스코트에 이름과 역할**을 준다. 웹툰 속 관찰자이자 퀴즈·게임 안내자로, 힌트와 축하를 맡는다.
- **학년별 문장 기준**: 1~2학년은 말풍선 하나에 한 문장, 20자 안팎, 쉬운 고유어. 3~4학년은 30자 이내. 5~6학년은 35자 이내이며 근거를 말하는 문장을 허용한다.
- 주의: `verify-episodes.cjs`는 모든 대사가 `production/storyboards.json` 프롬프트에 들어 있는지 검사한다. 대사를 바꾸면 스토리보드도 함께 갱신하거나, 검사를 "그림에 영향을 주는 필드"로 좁혀야 한다.

### 3-4. 목록(도서관)

- 선택한 학년을 기억하고, 처음 방문하면 "몇 학년이에요?"로 학년 선택을 유도한다.
- 학년 안에서는 **회차 목록형**(EP 순서, 썸네일, 제목, 4칸 진행 표시)으로 보여 주고 "이어 보기" 버튼을 둔다.
- 카드 구조를 고친다. 지금은 `<button>` 안에 `<h3>`·`<p>`가 들어 있어 규격에 맞지 않고, aria-label이 소개 문장을 가린다. `<article>` 안에 링크 하나를 두는 구조로 바꾼다.

## 4. 미니게임 개선: 배운 개념을 적용하는 게임

게임은 흐름의 마지막 단계다. 학생은 이미 웹툰을 읽고 개념 정리와 퀴즈, 활동까지 마쳤으므로, 게임은 같은 내용을 다시 묻지 않고 **배운 개념을 직접 써 보는 자리**가 되어야 한다.

### 4-1. 설계 원칙

1. **이야기의 문제를 숫자나 상황만 바꿔 다시 풀게 한다.** 예: 이야기에서는 예산 10,000원, 게임에서는 8,000원과 새 물건 목록. 그대로 베끼면 확인에 그치고, 조금 바꾸면 적용이 된다.
2. 시뮬레이션형은 **예상 → 해 보기 → 비교** 3단계를 거친다. 개념을 배운 뒤라 예상의 근거를 씨앗 문장에서 찾게 하고, 예상이 틀려도 괜찮다는 메시지를 준다.
3. **정답을 미리 보여 주지 않는다.** 목적("소풍 간식을 준비해요")은 주되 정답 목록은 감춘다.
4. **틀리면 이유를 알려 준다.** 오답마다 한 줄 이유(`why`)를 보여 주고 다시 해 볼 수 있다.
5. **별점 기준을 나눈다.** 시뮬레이션형은 탐구 단계(예상·실험·설명)를 마칠 때마다 별을 주고, 퀴즈형은 지금처럼 오답 수로 준다.
6. **캐릭터가 함께한다.** 시작·정답·오답·완료 때 학년별 지우·하린과 마스코트의 반응 이미지를 띄운다(6장 E·F 에셋).
7. 잠금은 현행대로 **활동을 마친 뒤 열린다.**
   - 버튼 이름을 "활동 마치고 게임 열기 →"처럼 결과가 보이게 바꾼다.
   - 잠긴 게임 영역에는 "④ 활동을 마치면 열려요"라고 조건을 보여 준다.
   - 활동을 다시 저장해도 진행 중이거나 끝난 게임 화면은 유지한다.

### 4-2. 엔진(게임 유형) 체계

| 엔진 | 상태 | 용도 | 핵심 데이터 |
|---|---|---|---|
| `coins` | 개선 | 돈 세기, 거스름돈 | 놀이 동전·지폐 이미지, `mode: 'make' \| 'change'` |
| `shop` | 신규(`budget` 대체) | 예산 장보기, 필요·욕구, 기회비용 | `budget`, `items[{name, price, icon, tag}]`(tag는 화면에 숨김), `events`(가격 인상 등), `reflect`(포기한 것) |
| `simulate` | 신규 | 이자, 저축 목표, 가격과 손님 수, 환율, 물가, 무역, 대출 | `model`(미리 정의한 계산 함수 이름), `params`(슬라이더), `predict`(예상 질문), `goal` |
| `ledger` | 신규 | 용돈 기입장, 통장 읽기, 수입·지출 | `start`, `rows[{memo, in, out}]`, 빈칸 지정 |
| `scenario` | 신규 | 권리, 안전, 금융 사기, 신용, 계약 | `nodes{ id: {text, panel?, choices[{label, next, feedback}]}}` |
| `portfolio` | 개선 | 분산 | 예상 단계, 결과 막대그래프, "전부 A" 비교 시각화 |
| `sort` / `match` / `order` | 유지·보강 | 개념 정리형 | 항목 6~8개, 고학년은 바구니 3개, 카드별 `why`, 그림 카드 |

`simulate` 예시(문자열 수식을 `eval`하지 않고, 모델 함수는 `games.js`에 미리 정의한다):

```json

  "type": "simulate",
  "model": "interest",
  "title": "사탕 저금통 실험",
  "mission": "사탕 10개를 맡기면 몇 주 뒤에 얼마나 늘어날까?",
  "predict": { "question": "4주 뒤 사탕은?", "options": ["10개 그대로", "조금 늘어나", "두 배가 돼"], "answer": 1 },

    { "key": "weeks", "label": "맡긴 기간", "min": 1, "max": 8, "step": 1, "unit": "주" },

  "fixed": { "principal": 10 },
  "goal": { "text": "기간이 길수록 이자가 쌓이는 걸 확인해요" }
```

### 4-4. 기존 유형 공통 보강

- 항목 수를 6~8개로 늘리고, 5~6학년 분류는 바구니 3개 이상으로 한다.
- 카드마다 `why`(오답 이유 한 줄)를 넣는다.
- 저학년은 그림 카드(아이콘 + 짧은 글)를 쓴다.
- 결과 화면에 캐릭터 반응을 넣는다. 이미 읽은 씨앗 문장을 반복하는 대신, 게임 결과와 씨앗 문장을 잇는 한 줄(`game.wrapUp`)을 보여 준다.
- 하드코딩 예외를 없앤다. 지금은 `games.js`에 `story.grade===3&&story.number===1`이면 단위를 "재료 조각"으로 바꾸는 코드가 있는데, `game.unit`으로 옮긴다.
- 조작은 탭 우선으로 한다(드래그는 보조). 키보드 조작과 `aria-live` 피드백을 유지하고, 터치 대상은 44px 이상으로 한다.

## 5. 개념 정리 · 퀴즈 · 활동 개선

### 5-1. 개념 정리 (웹툰 바로 다음)

1. **3컷 되짚기**: 웹툰의 문제·선택·결과 장면을 작게 다시 보여 주고, 그 아래에 씨앗 문장을 둔다. 데이터는 `recap: [0, 3, 7]`이고 기존 삽화를 재사용한다.
2. **오늘의 경제 씨앗**: 1~2학년은 한 문장, 3학년 이상은 두 문장 이내로 쓴다. "~하지 않아요" 같은 주의 문구보다 개념 설명을 먼저 둔다.
3. **핵심 용어 1~2개**를 뜻풀이와 함께 보여 준다(3-2의 용어 사전과 공유).

### 5-2. 퀴즈 90편 재작성 (가장 시급)

퀴즈가 개념 정리 바로 아래에 있으므로, 정답이 씨앗 문장의 복사본이면 읽기만 해도 맞힌다. 개념을 **이해했는지** 묻도록 다시 쓴다.

- 편마다 고유 질문을 쓴다. 이야기 사건을 묻는 `story`형과 새 상황에 적용하는 `apply`형을 학년마다 섞는다.
- 정답이 씨앗 문장을 베끼면 안 된다. 오답은 그 이야기에서 인물이 한 실수나 흔한 오개념으로 만든다.
- 선택지 길이를 맞추고(정답이 늘 제일 길면 안 됨), 정답 위치는 고르게 섞는다.
- 1~2학년은 짧은 선택지나 그림 선택지를 쓰고, 부정형 질문("아닌 것은?")은 피한다.
- 맞히면 해설(`explain`)을 보여 준다. 틀리면 장면 힌트(`hint`, `hintPanel`)와 "n장면 다시 보기" 버튼을 보여 준다.
- 데이터 예: `quiz: { kind, question, options[3], answer, explain, hint, hintPanel }`
- `scripts/verify-quizzes.cjs`를 추가해 위 규칙(질문 중복, 씨앗 문장과의 유사도, 길이 편차, 정답 위치 분포, 학년별 글자 수)을 자동으로 검사한다.
- 퀴즈 기록(`quiz: true`)의 의미는 그대로 두어 기존 기록과 호환한다.

### 5-3. 활동과 게임으로의 연결

1. **생활 미션과 내 생각**: 기록 입력은 선택으로 유지하고, 교사용 인쇄 활동지와 연결한다. 1~2학년은 "그림으로 했어요", "어른과 이야기했어요" 같은 체크 선택지를 둔다.
2. **저장 버튼**은 "활동 마치고 게임 열기 →"로 바꾸고, 저장 결과와 게임이 열렸다는 사실을 함께 알린다.
3. **게임 결과 화면**은 결과를 씨앗 문장과 내 활동 기록에 잇는다(2장, 4-4).
4. **스탬프판**: 학년별 15칸에 경제·노동·금융 색으로 찍는다. 학년을 완주하면 배지를 준다.

## 7. 디자인 시스템 제안

- **색 토큰**: `:root`에 브랜드, 영역 3색(경제 초록·노동 주황·금융 파랑), 캐릭터 색(지우 노랑·하린 초록), 상태색(정답·오답·잠금·힌트)을 정식으로 정의한다. 하린의 초록과 경제·브랜드 초록이 겹치니 명도나 채도로 구분한다.
- **글꼴**: CSS `@import`로 구글 글꼴을 불러오던 방식을 없애고, 자체 호스팅 woff2(한글 서브셋, 400·700 두 굵기)로 바꾼다. 제목용 둥근 서체 한 종을 쓸 경우 OFL 라이선스를 확인한다. 말풍선에는 손글씨체를 쓰지 않는다(초보 독자의 가독성이 떨어진다).
- **크기 기준**: UI 최소 12px, 본문 16px, 말풍선은 3-2 표를 따른다. 글자 대비는 4.5:1 이상으로 한다.
- **터치 기준**: 모든 버튼을 44×44px 이상으로 한다. 지금 작은 것은 장면 버튼 30~32px, 닫기 33px, 영역 버튼 높이 33px, 모바일 포트폴리오 ± 버튼 25px이다.
- **레이아웃**: 리더 전체 화면, 5단계 표시, 스티키 요소는 하나만 둔다(겹침 금지). 기준 폭은 360·390·768·1280px과 전자칠판 1920px이다.
- **학년별 톤**: 1~2학년은 큰 글자·그림 선택지·넘기기 모드, 3~4학년은 표와 기록, 5~6학년은 그래프·근거·토론 질문을 쓴다.
- **모션**: 정답·완료 효과는 짧게(300ms 안팎) 하고, `prefers-reduced-motion`을 지킨다.

## 8. 수업 실사용 필수 항목 (웹툰·게임 외)

- **선생님 안내**: 모바일에서도 접근할 수 있게 한다. 편마다 교사용 페이지(학습 목표, 발문 3개, 소요 시간, 인쇄용 활동지)를 둔다.
- **공용 기기 대응**: 서버 없이 별명 프로필(이모지와 별명, 실명 금지)을 고르게 한다. "내 기록 지우기"와 "기록 파일로 저장·불러오기(JSON)"를 넣는다.
- **성능 목표**: 첫 화면 1.5MB 이하, 목록 스크롤 중 이미지 합계 3MB 이하. 서비스 워커로 오프라인 캐시를 두는 것은 선택이다.
- **개인정보**: 외부 글꼴 호출을 없애 외부 요청이 0이 되게 한다. 메모란의 "이름·연락처 금지" 안내는 유지한다.
- **검증 자동화**: 퀴즈·게임·텍스트 길이 검사 스크립트를 추가한다. 주요 흐름(웹툰→개념 정리→퀴즈→활동→게임, 기록 유지)을 브라우저 스모크 테스트로 확인한다.

## 9. Codex 작업 묶음(WP)

### 공통 규칙 (모든 WP)

- 정적 HTML·CSS·JS를 유지한다. 프레임워크, 빌드 도구, 외부 CDN을 들이지 않는다. 개발용 일회성 스크립트는 `scripts/`에 둔다.
- 이야기 id(`g1-01`~`g6-15`)는 바꾸지 않는다.
- localStorage 키 `ecotoon-progress-v3`과 호환되게 한다. 스키마를 바꾸면 새 키로 옮기되 기존 키는 보존한다.
- 에셋 WP가 아니면 이미지 파일을 수정하지 않는다.
- 작업마다 `node scripts/verify-episodes.cjs`와 새 검사 스크립트를 통과시킨다.
- 360·390·768·1280px에서 직접 확인한다(전자칠판 관련 WP는 1920px도).
- WP 하나에 브랜치 하나와 PR 하나를 쓴다. 커밋은 작게 나눈다. README의 실행·검증 절을 갱신한다.
- 금융 내용은 놀이 돈과 가상 상황만 쓴다. 실제 상품, 브랜드, 투자 권유는 넣지 않는다.
